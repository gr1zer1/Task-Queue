# task_queue

Небольшая асинхронная очередь задач на Python с брокерами в памяти и Redis.

Проект показывает базовую схему:

- функция регистрируется через декоратор `@task`;
- клиент создает `Task` и кладет сообщение в очередь;
- `Worker` забирает задачу из брокера и выполняет функцию;
- состояние задачи сохраняется по `task.id`;
- сама функция ищется через стабильный `func_id`, а не через id конкретной задачи.

## Требования

- Python 3.11+
- Docker и Docker Compose для запуска Redis

## Быстрый старт

Запусти Redis:

```bash
docker compose up -d
```

Запусти пример:

```bash
python main.py
```

Ожидаемый вывод:

```text
3
7
11
```

## Пример задачи

```python
from task import task


@task(broker=broker)
async def add(a, b):
    return a + b
```

Вызов:

```python
task_result = await add.run(1, 2)
```

## Как устроено

- `task/` - модель задачи, сообщение для брокера и декоратор.
- `broker/` - абстрактный брокер, `MemoryBroker` и `RedisBroker`.
- `worker/` - выполнение задач.
- `client/` - простой клиент для отправки задач.
- `redis/` - минимальные функции кодирования/декодирования RESP-команд Redis.
- `registry.py` - глобальный регистр функций по `func_id`.

## RedisBroker

`RedisBroker` использует одно TCP-соединение на экземпляр. Для клиента и воркера в `main.py` создаются два брокера, потому что воркер выполняет блокирующий `BRPOP`, а клиенту параллельно нужны `SET`, `GET` и `LPUSH`.

## Статус проекта

Это учебная/экспериментальная реализация. Для production стоит добавить:

- нормальную обработку ошибок и reconnect Redis;
- тесты;
- отдельный формат ошибок задач;
- graceful shutdown воркера;
- пакетную структуру и конфигурацию.
